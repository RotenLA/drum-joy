# 修复内置 Preview 启动失败误报

## 已确认现象
- 截图中的页面来自应用自带的“启动超过 20 秒”监视层，不是手机与 Preview 的布局差异。
- 当前代码只在 20 秒时检查一次启动标记；监视层一旦出现，即使应用随后启动成功也不会被移除。
- 当前项目构建正常，内置 Preview 的歌曲接口也返回成功，未记录到页面运行错误；因此先按 Preview 重载较慢导致的误报处理，同时保留 Unity 真正启动失败时的诊断能力。

## 修改方案
1. 给启动失败层增加唯一标识和幂等保护，防止热更新或重复初始化叠加多个提示层。
2. 在页面真正启动后主动移除已出现的启动失败层，而不只设置启动完成标记。
3. 启动监视期间持续观察完成状态；Preview 即使超过 20 秒才完成加载，也会自动恢复正常界面。
4. 保留 Unity / Android WebView 的真实失败提示、错误采集、UA 信息和重新加载按钮，不通过简单关闭监视功能掩盖真故障。
5. 对 Lovable 内置 Preview 给予更合理的等待时间，避免构建刷新期间误报；正式网页和 Unity 仍使用严格的启动检测。

## 验证
- 在内置 Preview 重新加载并等待超过原 20 秒阈值，确认不会停留在误报页面。
- 模拟延迟启动，确认提示层出现后可在应用完成启动时自动消失。
- 模拟真正未启动，确认诊断页仍会显示且“重新加载”可用。
- 检查手机页面与 Unity 使用的启动检测没有退化，并确认构建及页面错误记录正常。
