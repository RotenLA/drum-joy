# 选歌界面滑动、歌名样式与「暂停退出」修复

## 1. 选歌可左右滑动

当前歌曲卡片横排虽然能溢出，但只能靠滚轮/触摸，桌面上鼠标拖不动，且首尾卡片贴边无法滑出。改造：

- 支持鼠标按下拖拽横向滑动（拖动时不触发点击）、滚轮横向滑动、触摸滑动惯性保留。
- 列表左右各留出足够空白，使任意一首歌都能滑到屏幕中央；滑到两端时最外侧那首只露出一部分在界面内。
- 选中某首歌时自动把它平滑滚动到可见位置。
- 歌曲较多时，左右边缘加淡出渐变提示还有内容。

## 2. 歌名字体与竖排显示

未选中的窄卡片：

- 歌名字号放大（比现在明显更大、更易读）。
- 文字逆时针 90° 竖排，贴着卡片右侧显示（跟随卡片斜切角度）。
- 歌名过长时不再截断，改为在卡片高度内循环滚动（marquee），滚完停顿再循环。

选中的宽卡片保持现在的横排大标题样式，标题过长时同样改为横向滚动而非截断。

## 3. Bug：中途暂停退出后的两个问题

确认到的两处原因：

- **历史演奏里没有这首歌**：历史只在歌曲完整结束时写入，中途退出不记录。
  改为：只要真正开始演奏过（进入过演奏状态且有击打/经过一定时长），暂停退出时也写入一条记录，标注为未完成，并记录当时的准确率、最大连击与进度百分比。历史列表中未完成的记录显示进度（例如「未完成 43%」）。
- **退回选歌后「开始」和「设置」不见了**：选歌层的「已就绪」状态是它自己的临时状态，演奏时选歌层被卸载，退回来后这个状态被清空，所以按钮不显示，尽管歌曲其实还加载在内存里。
  改为：就绪状态改由「当前歌曲是否已加载完成」这一全局事实判断，不再依赖选歌层的临时状态。这样中途退出回到选歌界面，这首歌依然是选中+已就绪，「开始」「设置」照常显示，可直接重开。

## 技术细节

- `src/taiko/SongPicker.tsx`：新增滚动容器 ref + 指针拖拽逻辑（pointerdown/move/up，位移超过阈值则吞掉 click）、`scrollPaddingInline` 式左右留白、选中项 `scrollIntoView`；窄卡片标题改为 `rotate(-90deg)` 靠右定位容器 + CSS marquee 动画；`ready` 改为从 `useSong()` 派生（`song.songId === item.id && song.stems` 等已加载条件），删除本地 `ready` state。
- `src/taiko/FallScreen.tsx`：暂停遮罩中「选择歌曲」按钮在切回 idle 前调用一次 `addHistory`（带 `completed: false` 与进度），并做去重，避免同一局重复写入。
- `src/taiko/history.ts`：`HistoryEntry` 增加可选 `completed?: boolean` 与 `progress?: number`（0~100）。
- `src/styles.css`：新增 marquee keyframes 与边缘渐变遮罩工具类。
