# 位置捕捉修复：流程不再卡在第一项

## 现象

第一个鼓面的左棒采完 3 次后，流程不再前进（不跳到右棒，也不跳到下一个鼓面），并且屏幕上看不出到底卡在哪一步、为什么不计数。

## 诊断（未最终确认，先按可疑点全部消除）

当前采集流程把「当前第几项」「当前已采几次」「是否在采集」分散存在三个状态里，并用一个 350 毫秒的延时回调去推进下一项，同时用几个中间变量读取这些状态。这类写法在击打事件里读到的可能是旧值，一旦某一次读旧值，推进就会永久停住。同时右棒姿态若在那一刻缺失，采集会被静默拒绝，界面上也看不到原因。

因此本轮不做小补丁，把采集流程改成一个不依赖延时和中间变量的单一状态机，并把每一次拒绝的原因显示出来，让「为什么不动」肉眼可见。

## 修改内容

1. 采集状态合并为一个对象（当前项、当前手、已采次数），所有更新都基于上一次的值计算，推进立即发生，去掉 350 毫秒延时。
2. 完成一项后立刻高亮下一项；全部 14 组（7 个鼓面 × 左右）完成后进入总览。
3. 右侧新增左右棒各自的在线指示，分开显示，而不是合成一个「左右鼓棒姿态」。
4. 开始条件放宽为「当前这只手的姿态有效」即可，不再要求两只棒同时在线。
5. 击打被拒绝时在提示区明确写出原因：敲错鼓面、该手姿态缺失、音符未映射；同一鼓面 60 毫秒内的重复音符按一次处理，避免一次击打被算两次。
6. 增加手动控制：「上一项」「下一项」「跳过本项」「重置本项」，任何情况下用户都能自己往下走。
7. 提示区放大显示当前目标：鼓面名 + 左/右棒 + 进度 `2/3`，并在鼓阵上继续高亮当前鼓面。

## 不改动的部分

鼓面顺序、每组 3 次、去异常值取中位数、离散度、仿射拟合、本地保存、导出/导入/恢复默认的文件格式与键名全部保持不变；已采集的数据仍然兼容。

- `src/taiko/stickCalibration.ts`：如需，仅补充按单侧判断是否完成的小工具函数，文件格式不变。
