# 后台导出通用歌曲谱面包

## 目标

- 保留现有后台的上传、重算与上架流程，不改变玩家端曲库。
- 为每首已入库歌曲导出一个轻量、稳定、与具体玩法画面无关的通用 JSON 谱面包。
- 其他音游可直接读取时间、鼓件、四档难度与动态节拍，不需要重新分析 MIDI。

## 后台功能

1. 在曲库每首歌旁增加「导出谱面」按钮，下载该歌曲的 `.aerogame-chart.json` 文件。
2. 在曲库顶部增加「批量导出」按钮，将当前后台中的歌曲汇总为一个 JSON 文件，便于整体迁移。
3. 导出过程中显示状态；单首数据缺失或格式异常时给出明确提示，不生成残缺文件。
4. 导出操作继续沿用现有后台登录校验，不开放新的公共下载入口。

## 通用格式

- 根节点包含格式名称、`schemaVersion`、导出时间和生成来源，方便以后升级兼容。
- 每首歌包含稳定 ID、标题、艺人、时长、BPM、拍号和谱面指纹。
- 四档谱面统一导出：`easy`、`beginner`、`standard`、`hard`。
- 每个音符保留：毫秒时间、标准鼓件/轨道、原始 MIDI note、重击标记和可选持续时间。
- 保留谱面自身的 `grid` 与 `beatMap`；有 Metro 动态拍点时，其他游戏可以逐拍精确对齐。
- 文件内附轨道含义与时间单位，避免接入方依赖当前游戏的画面布局或内部代码。

## 文档与接入示例

- 增加一份中文格式说明，列出字段、四档名称、鼓件映射、时间基准和版本兼容规则。
- 增加一个简短的 TypeScript 读取示例，演示加载文件、选择难度并按 `timeMs` 读取音符。
- 当前先固定 AeroGame 通用 JSON；以后拿到其他音游的目标格式样例，可在此基础上增加转换器，不修改数据库里的原谱。

## 技术说明

- 后台服务只返回导出所需的歌曲元数据与当前指纹对应的四档谱面；不返回音频路径、签名链接或管理凭据。
- 浏览器负责生成并下载 JSON，避免在服务端暂存导出文件。
- 不新增数据表，也不改变现有谱面生成算法、上架状态或玩家下载逻辑。
- 单首和批量导出共用同一份格式构建与校验代码，避免字段漂移。

## 验证与交付

- 验证单首、全部歌曲导出，文件名可读且中文歌名正常。
- 验证四档数量、音符时间顺序、鼓件字段、`grid`/`beatMap` 与数据库当前谱面一致。
- 验证未登录不能导出，导出不会暴露音频存储路径或后台敏感信息。
- 检查后台原有上传、重算、上下架、标签和删除功能不受影响。
- 将全部新增/修改源码及格式文档按原路径打包为 ZIP，附简短文件清单。
