# 教学与游玩鼓棒切层修正

## 目标

保留硬件已经明确提供的左右双鼓棒：`l` 始终对应左侧蓝棒，`r` 始终对应右侧橙棒，不重新分配颜色或身份。

敲击发生时，不再要求 Unity 额外告诉网页是哪只手，也不按固定左右区域猜测；直接比较两根鼓棒在该时刻的真实姿态，选择实际指向被敲鼓面的那一根执行上下层切换。

## 实施内容

1. **保持双棒身份不变**
   - 继续使用宿主姿态数据中的 `l` / `r`。
   - 左右棒的颜色、位置、角度和运动轨迹保持一一对应。
   - 教学和正式游玩共用同一套处理。

2. **按当前指向选择切层鼓棒**
   - 每次有效敲击时，读取左右棒最新的 pitch / yaw。
   - 按目标鼓面所在的上层或下层，分别计算两根棒在该层的指向位置。
   - 选择与被敲鼓面中心更接近的那根棒切换层级；另一根保持原层。
   - 某根棒断连或姿态过期时，只使用仍在线的那根。
   - 踏板不触发鼓棒上下层切换。

3. **继续遵守难度可见鼓面**
   - 正式游戏只有当前难度实际显示的鼓面能触发切层。
   - 未显示鼓面的 MIDI 即使到达，也不改变任何鼓棒层级。
   - 教学展示全部鼓件，因此教学中的上四鼓面和下三鼓面都可触发。

4. **简化宿主接口约定**
   - 鼓棒左右继续完全由 `__pd2uSticks` 的 `l` / `r` 决定。
   - `__pd2uNoteOn` 不再要求新增手别参数，维持原有 note、力度、时间戳调用方式。
   - 更新 Unity 与安卓对接说明，避免开发误以为还要重复传左右手。

5. **验证**
   - 验证蓝棒只跟随 `l`、橙棒只跟随 `r`。
   - 分别测试两根棒指向上层/下层鼓面时，仅正确的棒切层。
   - 测试双棒交叉、单棒断连、姿态过期和目标距离接近的情况。
   - 覆盖四档难度与教学，确认隐藏鼓面不会触发切层。
   - 检查桌面及手机横屏，无跳层、越过中线或画面报错。

## 技术说明

当前姿态接口已经明确拆分 `l` / `r`，渲染也固定按左右身份绑定双色鼓棒。修改重点仅是切层归属算法：使用目标层的实际映射坐标比较两根棒与目标鼓面的距离，而不是增加新的手别来源。上下层仍采用 150ms 平滑过渡，层内 Y 轴只做轻微跟随并严格限制在中线两侧。
