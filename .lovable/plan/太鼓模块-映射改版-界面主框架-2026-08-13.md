# 太鼓模块：映射改版 + 界面主框架

分两块：先把「咚/嗒」映射按双脚/双手重新定义，再搭一个带侧边导航的主框架，把三个屏幕的壳先立起来。

## 一、映射改版

新规则（覆盖之前的上/下分组）：

- 咚（DON，红，双脚）：36 底鼓、44 踩镲踏板
- 嗒（KA，蓝，双手）：其余所有已知鼓件音符 —— 35、38、40、41、42、43、45、46、47、48、49、50、51、52
- 未列出的音符：返回 null，调用方忽略

`src/shared/drumLaneMap.ts` 改为：
- `DrumLane = 'don' | 'ka'`
- `FOOT_NOTES = [36, 44]`、`HAND_NOTES = [...]`
- `getDrumLane(note)` 返回 `'don' | 'ka' | null`
- 保留 `DRUM_NOTE_NAMES` 与 `getDrumNoteName`
- 旧的 `'up' | 'down'` 命名一次性替换，不做兼容别名（模块目前无外部调用方）

同步更新 `docs/drum-lane-map.md`。

## 二、界面：主框架 + 三屏

运行环境我定为「应用内新页面」——复用现有 MIDI 输入管线与设备设置，游玩屏支持一键切全屏，不再单开窗口，避免两套音频/MIDI 生命周期。

布局：左侧窄导航（图标+文字），右侧内容区。

```text
┌────────┬──────────────────────────────┐
│ 太鼓    │  顶栏：曲目名 / BPM / 拍号     │
│ ● 游玩  ├──────────────────────────────┤
│ ○ 谱面  │                              │
│ ○ 映射  │        当前屏内容              │
│        │                              │
└────────┴──────────────────────────────┘
```

三个屏，本轮各自出静态可交互骨架（无真实音频/判定逻辑）：

1. 游玩屏 Play
   - 横向单轨道，左侧固定判定圈，音符从右往左走
   - 红圆＝咚、蓝圆＝嗒，大圆＝重击（预留）
   - 顶部：连击数、当前得分、进度条
   - 本轮用一段假谱面数据 + requestAnimationFrame 驱动滚动，验证观感

2. 谱面屏 Chart
   - 上半：整曲缩略条，按小节切分
   - 下半：分小节展开的谱面网格，每行一小节，格子显示咚/嗒/空
   - 侧栏显示 BPM、拍号、总音符数、咚/嗒占比
   - 支持点击某小节跳到游玩屏对应位置（占位回调）

3. 映射屏 Mapping
   - 左：鼓组示意图（简化俯视图 SVG），鼓件按当前分组着色
   - 右：音符列表，每行「音符号 / 名称 / 咚·嗒·忽略」三态切换
   - 顶部「恢复默认」按钮
   - 本轮状态存在本地 state，不落盘

## 三、视觉

极简纸墨：底 #f5f3ee、面 #e8e4dd、咚 #d9463e、嗒 #2f6fb0、墨字 #1f1d1a。
- 全部写成 CSS 变量语义 token（`--paper`、`--surface`、`--don`、`--ka`、`--ink`），组件不写死颜色
- 无渐变、无阴影堆叠；用 1px 墨线分隔与细边框
- 字体：标题用等宽/几何无衬线，数字（BPM、连击）用 tabular-nums
- 动效克制：音符滚动线性，判定命中只做一次短促缩放

## 技术说明

- 纯前端组件，React + TS，样式走 Tailwind + CSS 变量
- 目录：`src/taiko/` 下放 `PlayScreen.tsx`、`ChartScreen.tsx`、`MappingScreen.tsx`、`TaikoShell.tsx`，共享类型放 `src/shared/`
- 游玩屏用单个 canvas 绘制音符轨道（DOM 节点数不随音符增长），其余屏用普通 DOM
- 谱面数据结构先定死：`{ bpm, timeSignature, notes: { timeMs, lane }[] }`，后续 BPM/拍号识别模块直接产出这个结构
