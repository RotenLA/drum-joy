# 本次变更（演奏界面顶部细节调整）

## 问题分析：左上角 IN / LF

- **IN** 表示「输入延迟」= 宿主/MIDI 把敲击事件交给网页的时刻，到网页实际处理该事件的时刻之差（毫秒）。
  - 显示 `IN -/-ms` 表示最近没有敲击样本；有敲击后显示当前值 / 最近 50 次最大值。
  - 如果 IN 数值在跳而 LF 没涨，说明抖动主要来自宿主侧；如果 IN 接近 0 而 LF 在涨，说明是网页主线程卡顿。
- **LF** 表示「长帧」= 渲染帧间隔超过 30ms 的次数，括号里是最近一次长帧的耗时。
  - 用于直接观察网页掉帧、绘制卡顿。

本次没有改这两个数值的计算逻辑，只是把显示面板做得更易读：加深半透明衬底、调大字号、增加 tooltip，无数据时显示 `-` 避免误解。

## 修复内容

1. **左上角 FPS / IN / LF 量表可读性提升**
   - 增加深色半透明衬底与轻微背景模糊，提升在舞台背景上的辨识度。
   - 无敲击数据时 IN 显示 `-/-ms`，避免「0ms 延迟」的误导。
   - 保留指针穿透，不遮挡鼓盘与音符。

2. **右上角暂停按钮与歌名重叠修复**
   - 将歌曲信息（歌名、速度、难度、BPM）与暂停按钮由横向并排改为纵向叠放：信息在上，暂停按钮和 HelpDot 在下。
   - 歌名超长时自动截断，避免与下方按钮重叠。
   - 保留所有现有暂停/继续逻辑。
